01 / ENGINE ECOSYSTEM

引擎生态全景

Paimon 设计之初就以"开放存储"为核心理念，支持主流计算引擎通过统一协议读写，真正实现一份数据、多引擎协作。

Flink

Apache Flink（深度集成）

Paimon 由 Flink 社区孵化，与 Flink 的集成最为深度。支持流批一体读写、Lookup Join、Changelog 消费、Exactly-Once 语义，是最推荐的写入引擎。

流批一体 Lookup Join Exactly-Once CDC 摄取
Spark

Apache Spark（批量处理）

通过 Paimon Spark Connector 接入，支持 DataFrame/SQL 读写、批量 OVERWRITE、时间旅行查询、Schema Evolution 感知，是离线 ETL 和大规模数据回填的首选。

DataFrame API Spark SQL 时间旅行 批量回填
StarRocks

StarRocks（实时 OLAP）

通过 External Catalog 直接读取 Paimon 表，无需数据导入。结合 StarRocks 的向量化执行引擎，实现亚秒级 OLAP 查询，是实时数仓查询层的首选搭配。

External Catalog 向量化查询 亚秒级响应
Hive

Apache Hive（离线查询）

通过 HiveCatalog 将 Paimon 表注册到 HMS，Hive SQL 可直接查询，兼容现有 Hive 生态工具链。适合将 Paimon 渐进式引入已有 Hive 数仓体系。

HiveCatalog HMS 兼容 渐进式迁移
Trino

Trino / Presto（联邦查询）

通过 Hive Connector 兼容读取 Paimon 表（ORC/Parquet），支持联邦查询跨数据源 JOIN。适合数据探索和 Ad-hoc 查询场景，写入能力受限。

Hive Connector 联邦查询 只读
Doris

Apache Doris（MPP 查询）

通过 Paimon Catalog 直连，支持 Doris 直接查询 Paimon 表，利用 Doris 的 MPP 架构加速复杂聚合查询。与 StarRocks 功能相近，适合已有 Doris 体系的团队。

Paimon Catalog MPP 加速 复杂聚合

Flink SQL — Lookup Join 完整示例
-- 维度表（Paimon Primary Key Table，用于 Lookup Join）
CREATE TABLE dim_user (
  user_id    BIGINT,
  username   STRING,
  city       STRING,
  vip_level  INT,
  PRIMARY KEY (user_id) NOT ENFORCED
) WITH (
  'connector'   = 'paimon',
  'warehouse'   = 'hdfs:///warehouse/paimon',
  'lookup.cache-rows'    = '100000',   -- 本地 RocksDB 缓存行数
  'lookup.cache-ttl'     = '10 min',   -- 缓存 TTL（维表更新频率决定）
  'lookup.async'         = 'true'      -- 异步 Lookup（提升吞吐）
);

-- 主流事实表（Kafka CDC）
CREATE TABLE ods_orders (
  order_id    BIGINT,
  user_id     BIGINT,
  amount      DECIMAL(12,2),
  proc_time   AS PROCTIME()   -- Lookup Join 需要处理时间
) WITH ( 'connector' = 'kafka', ... );

-- Lookup Join 实现维度扩展
INSERT INTO dwd_orders
SELECT
  o.order_id, o.user_id, o.amount,
  u.username, u.city, u.vip_level
FROM ods_orders AS o
LEFT JOIN dim_user FOR SYSTEM_TIME AS OF o.proc_time AS u
  ON o.user_id = u.user_id;

-- ✓ 首次 Lookup：从 Paimon 远程读取，写入本地 RocksDB
-- ✓ 再次 Lookup 相同 key：直接从 RocksDB 返回，延迟 <1ms
-- ✓ TTL 过期后：自动从 Paimon 重新加载最新版本
Flink SQL — partial-update 多流合并宽表
-- 场景：订单主表 + 物流信息 + 支付信息 → 合并为宽表
-- 使用 partial-update，每个流只写自己负责的列

CREATE TABLE dws_order_wide (
  order_id      BIGINT,
  -- 订单流字段
  user_id       BIGINT,
  amount        DECIMAL(12,2),
  -- 物流流字段
  logistics_no  STRING,
  ship_time     TIMESTAMP(3),
  -- 支付流字段
  pay_method    STRING,
  pay_time      TIMESTAMP(3),
  PRIMARY KEY (order_id) NOT ENFORCED
) WITH (
  'merge-engine'        = 'partial-update',
  'partial-update.ignore-empty-columns' = 'true'  -- 空列不覆盖
);

-- 流1：订单主流写入（只写订单字段）
INSERT INTO dws_order_wide (order_id, user_id, amount)
SELECT order_id, user_id, amount FROM ods_orders;

-- 流2：物流流写入（只写物流字段）
INSERT INTO dws_order_wide (order_id, logistics_no, ship_time)
SELECT order_id, logistics_no, ship_time FROM ods_logistics;

-- 流3：支付流写入（只写支付字段）
INSERT INTO dws_order_wide (order_id, pay_method, pay_time)
SELECT order_id, pay_method, pay_time FROM ods_payment;
PERFORMANCE TIP
Lookup Join 的 lookup.async=true 可将同步阻塞等待改为异步回调，在高并发场景下吞吐提升 2～5 倍。但需同时设置 lookup.async-capacity（默认 100）控制并发异步请求数，防止 Paimon 端过载。
03 / SPARK INTEGRATION

Spark 集成实战

Spark 是离线批处理和大规模数据回填的主力引擎，通过 Paimon Spark Connector 可以无缝接入现有 Spark 工作流。

Spark 读取能力

全量读取最新 Snapshot（批量扫描）
时间旅行查询（按 snapshot-id 或 timestamp）
增量读取（两个 snapshot 之间的 diff）
分区裁剪 + 列裁剪 + 统计信息下推
自动感知最新 Schema（Schema Evolution）
并发读取多个 Bucket（并行 Split）

Spark 写入能力

Append 追加写入（Append-Only 表）
INSERT OVERWRITE 分区覆盖写
BulkWrite 高吞吐批量写入
DataFrame.write.format("paimon") API
写入后自动触发 Compaction（可配置）
Dynamic Partition 覆盖（自动推断分区）
Spark — 完整读写示例（DataFrame API + SQL）
// ── Spark 环境初始化 ──────────────────────────────────────
val spark = SparkSession.builder()
  .config("spark.sql.catalog.paimon", "org.apache.paimon.spark.SparkCatalog")
  .config("spark.sql.catalog.paimon.warehouse", "hdfs:///warehouse/paimon")
  .config("spark.sql.catalog.paimon.metastore", "hive")
  .config("spark.sql.catalog.paimon.uri", "thrift://hive-metastore:9083")
  .getOrCreate()

// ── 全量读取最新数据 ──────────────────────────────────────
val df = spark.read.format("paimon")
  .load("hdfs:///warehouse/paimon/my_db.db/orders")

// ── 时间旅行查询 ──────────────────────────────────────────
val histDf = spark.read.format("paimon")
  .option("scan.snapshot-id", "42")          // 按 snapshot ID
  .option("scan.timestamp-millis", "1704067200000")  // 按时间戳
  .load("hdfs:///warehouse/paimon/my_db.db/orders")

// ── 增量读取（两快照之间的变化）────────────────────────────
val incrDf = spark.read.format("paimon")
  .option("incremental-between", "40,42")    // snapshot 40 到 42 的增量
  .load("hdfs:///warehouse/paimon/my_db.db/orders")

// ── 分区覆盖写（T+1 数据修正）────────────────────────────
df.write.format("paimon")
  .mode("overwrite")
  .option("partitionOverwriteMode", "dynamic") // 动态分区覆盖
  .save("hdfs:///warehouse/paimon/my_db.db/orders")

// ── Spark SQL 方式 ─────────────────────────────────────
spark.sql("""
  INSERT OVERWRITE paimon.my_db.orders PARTITION (dt = '2024-01-01')
  SELECT order_id, user_id, amount FROM source_table
  WHERE dt = '2024-01-01'
""")
IMPORTANT
Spark 写入 Paimon Primary Key Table 时，默认走 BulkWrite 路径，不支持实时 Upsert 语义（无法合并旧版本记录），只能整体 OVERWRITE 分区。若需要 Upsert，应使用 Flink 流式写入。Spark 更适合做全量数据初始化和分区级覆盖修正。
04 / OLAP ENGINE INTEGRATION

OLAP 引擎集成实战

将 Paimon 作为存储层，搭配 StarRocks 或 Doris 作为查询层，是目前最流行的实时数仓架构，兼顾数据新鲜度和查询性能。

StarRocks — 创建 Paimon External Catalog
-- StarRocks 创建 Paimon External Catalog
CREATE EXTERNAL CATALOG paimon_catalog
PROPERTIES (
  "type"                    = "paimon",
  "paimon.catalog.type"     = "hive",
  "hive.metastore.uris"     = "thrift://hive-metastore:9083",
  "aws.s3.access_key"       = "your-access-key",   -- S3 存储时配置
  "aws.s3.secret_key"       = "your-secret-key",
  "aws.s3.region"           = "cn-northwest-1"
);

-- 直接查询 Paimon 表（无需数据导入）
SET CATALOG paimon_catalog;
USE my_db;

-- 实时查询（读取 Paimon 最新 Snapshot）
SELECT
  city,
  COUNT(*) AS order_cnt,
  SUM(amount) AS total_gmv
FROM dwd_orders
WHERE dt = CURDATE()
GROUP BY city
ORDER BY total_gmv DESC
LIMIT 20;

-- 跨 Paimon + StarRocks Native 表的联邦查询
SELECT
  p.user_id, p.city,
  n.credit_score   -- StarRocks native 表
FROM paimon_catalog.my_db.dwd_orders p
JOIN default_catalog.risk_db.user_credit n
  ON p.user_id = n.user_id;
Hive — 通过 HiveCatalog 兼容访问
-- Flink SQL 注册 HiveCatalog（让 Hive/Trino 可见 Paimon 表）
CREATE CATALOG hive_catalog WITH (
  'type'             = 'paimon',
  'metastore'        = 'hive',
  'uri'              = 'thrift://hive-metastore:9083',
  'warehouse'        = 'hdfs:///warehouse/paimon',
  'lock.enabled'     = 'true'   -- 多引擎并发写入时开启分布式锁
);

USE CATALOG hive_catalog;

-- Paimon 表自动在 HMS 中注册，Hive/Trino/Impala 可直接查询
-- Hive SQL:
-- SELECT * FROM paimon_db.dwd_orders WHERE dt = '2024-01-01';

-- Trino/Presto（通过 Hive Connector 兼容）:
-- SELECT * FROM hive.paimon_db.dwd_orders LIMIT 100;

-- 多引擎并发读写注意事项：
-- ✓ 多引擎并发读：完全支持，各引擎读各自 Snapshot
-- ✓ 单引擎写 + 多引擎读：完全支持
-- ⚠ 多引擎并发写：需开启 lock.enabled=true，通过 HMS 锁协调
-- ✕ 多引擎同时 OVERWRITE 同一分区：有数据冲突风险，避免

06 / ADVANCED INTEGRATION PATTERNS

高级集成模式

基于前五章的原理积累，这些高级模式将 Paimon 的能力发挥到极致，是区分初级用户和高级用户的关键技能。

①
PATTERN — 流式物化视图

流式分层物化视图

多个 Flink 作业串联：ODS → DWD → DWS，每层均写入独立 Paimon 表，每层的 changelog-producer 设为 input，下游作业以流模式消费上层产出的 Changelog，实现全链路增量计算。整体延迟可控制在 2～5 分钟以内，彻底替代传统离线调度链路。

②
PATTERN — 双写保险策略

Flink + Kafka 双写保险

写入 Paimon 的同时，将同样数据写入 Kafka Topic 作为备份。当 Paimon 需要回滚或重建时，可从 Kafka 重新回放数据，无需依赖上游数据源重新全量同步，显著降低 RTO（恢复时间目标）。适合对数据可用性要求极高的核心业务表。

③
PATTERN — 聚合引擎下推

Aggregation Merge Engine 预聚合

使用 merge-engine=aggregation 将 SUM/MAX/MIN/COUNT 等聚合操作下推到 Paimon 写入层，每次写入自动与存量数据合并。上层 StarRocks 查询时读到的已经是聚合结果，无需再做全量聚合扫描，查询性能提升 10x+，适合实时大屏/计数器类场景。

④
PATTERN — 多活写入

多地域多活写入协调

两个机房的 Flink 作业同时向同一 Paimon 表写入（不同 Bucket 分区），通过 sequence.field 和 HMS 分布式锁保证写入幂等性和顺序性。Snapshot Commit 通过 HDFS/S3 的原子操作保证一致性，实现跨机房的数据合流。

⑤
PATTERN — 数据对账

基于 Tag 的数据对账体系

每日业务收盘后，对核心业务表创建 Tag（如 daily-2024-01-01），对账系统通过 Spark 读取 Tag 对应版本进行历史对比，无需专门维护对账数据副本。对账差异时，可精确追溯到哪个 Snapshot 开始出现偏差，排查效率大幅提升。
